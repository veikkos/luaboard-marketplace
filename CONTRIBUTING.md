# Contributing

Send a pull request with a new app or a change to one. Pull requests are
reviewed before they are merged. The API apps can use is in luaboard's
[docs/LUA_API.md](https://github.com/veikkos/luaboard/blob/main/docs/LUA_API.md),
and the existing apps are good examples.

## An app's folder

One folder per app, at the top of the repository. The folder name is the
app's name on the board: 1 to 23 characters from `A-Z a-z 0-9 _ . -`, and
different from every other app's name, also ignoring case.

- `main.lua`: where the app starts. More `.lua` files can sit next to it.
- `app.json`: the app's details.
- `LICENSE`: the app's license.
- `README.md`: what the app does, then Setup, then any sections on using
  it, then Development, and last notes on the code and the service's terms.
  Setup is for people using the app: getting it (Marketplace on the board,
  the studio or `luaboard install`), and its keys and login, if any.
  Development is for people working on it from a clone of this repository:
  `secrets.env` and simulator commands.
- Optional: images (`.jpg`, `.jpeg`, `.png`) and sounds (`.wav`) the app
  uses, screenshots for the README in `img/`, `secrets.env.example`.

Only the `.lua` files, `app.json`, and the `.jpg`, `.jpeg`, `.png` and `.wav`
files at the app's top level go to the board. Everything else, `img/`
included, stays in the repository. Other subfolders are not used.

## app.json

```json
{
  "title": "Clock",
  "description": "The time and date, digital or analog.",
  "version": "1.0.0",
  "author": "Your Name",
  "license": "MIT",
  "lua_api": 1
}
```

- `version` is `MAJOR.MINOR.PATCH`, with no pre-release or build part. Bump it
  with every change to a file that goes to the board: boards only get a
  change when the version goes up, so the checks refuse a change without
  one.
- `lua_api` is the luaboard Lua API version the app is written for (see
  LUA_API.md).
- `license` names the app's license, like `MIT`.
- `title` is the app's name in the menu.
- `description` says what the app does, in a sentence or two. The board
  shows it in three lines of 48 characters (the app's options), and for an
  app that needs setup, in four lines of 26 beside a QR code (its
  Marketplace page). Every character counts as one, `ä` and `W` too: the
  font gives each the same width.
- The board keeps at most 31 bytes of `title` and `author` and 23 of
  `license` (UTF-8: `ä` is two). The checks refuse text that the board
  would cut, and a description that doesn't fit its lines.

## Licensing

Each app has a `LICENSE` file and names the same license in `app.json`. MIT
is always accepted. Any other license is decided case by case in the pull
request, and may be declined: the apps here are meant to be open source.

Images and sounds fall under the app's license, so only add ones you made or
may share that way. An app that talks to an outside service says in its
README that users need their own account and follow that service's terms.
Never commit anyone's keys.

## Secrets and setup

An app that needs keys or a login:

- ships a `secrets.env.example` with every secret's name and a comment saying
  where to get it (never real values, and `secrets.env` itself is
  gitignored). Leave a key the app can't do without empty (`api_key=`); give
  an optional one a default (`place=Helsinki`) or comment it out. The board
  marks the app "needs setup" when a key is left empty,
- gives the `luaboard secrets set <app> <name> <value>` commands in its
  README's Setup section, and `secrets.env` in its Development section,
- shows a setup screen when something is missing: at least what's missing
  and where the steps are (`github.com/veikkos/luaboard-marketplace`, or the
  app's own README address if it fits). Boards can install apps directly,
  so this screen may be the first thing a user sees. The board's Marketplace
  page also shows the README's address and a QR code of it.

## index.json

`index.json` is generated by `tools/build_index.py` after every push to
`main`. Don't edit it. The script stops on a broken app (a missing
`LICENSE`, a version that isn't `MAJOR.MINOR.PATCH`, board files changed
without a new version, and the like). To check your app before sending it,
`git add` it (the script reads only files git knows) and run:

```sh
python3 tools/build_index.py --previous index.json --out /tmp/index.json
```
